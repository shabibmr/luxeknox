# Module 0 — Fix Register

Remediation for the findings in [`todo/review/M0-01-to-M0-24-standards-spec-review.md`](../review/M0-01-to-M0-24-standards-spec-review.md).

**Rule:** each task touches at most 7 files (same rule as Module 0).
**Rule:** each task lands green — `pnpm --filter api lint typecheck test` passes before the next task starts.

**Status:** in progress

## Goal

Module 0 is feature-complete but has four defects that make it unsafe to build on: auth bodies are unvalidated, the audit-log immutability control does not actually apply, the repository layer ADR-0004 mandates is bypassed in the auth path, and the pagination default never reads `gym_settings`. Everything else here is cleanup that stops those four from recurring.

## Corrections to the review

Two review findings were re-checked against the code and do **not** hold. They are recorded here so nobody "fixes" them:

| Claim | Verdict |
| :--- | :--- |
| `seed/admin.ts` hashes with argon2i because `argon2.hash()` has no options (Standards #4) | **False.** `argon2@0.41.1` (`node_modules/.pnpm/argon2@0.41.1/.../argon2.cjs:30-37`) defaults to `type: argon2id`. The hash is correct. Only the *duplication* is real — see [F-11](./F-11-seed-hygiene.md). |
| Email lookup is case-sensitive so throttling and login disagree (earlier caveman review) | **False.** `users.email` is `utf8mb4_0900_ai_ci`; MySQL `=` under a `_ci` collation is already case-insensitive. |

Findings from the earlier caveman review that are **already fixed** in the current tree and need no task: access-token 30-minute TTL (`session.repository.ts:25,31`), `createSession` returning the real `insertId` (`session.repository.ts:58-61`), both guards bound as `APP_GUARD` (`auth.module.ts:21-24`, `rbac.module.ts:10-13`), `@CurrentUser` throwing when unauthenticated (`current-user.decorator.ts:15-17`).

## Three defects the review missed

Found while verifying the reports:

1. **The audit-immutability e2e test can never fail.** `test/settings.e2e.spec.ts:85-94` wraps the `UPDATE audit_logs` in `try { ... } catch { expect(...) }`. If the UPDATE *succeeds* — the actual current behaviour — the test passes silently. The one check guarding M0-11's acceptance criterion is a no-op. → [F-03](./F-03-least-privilege-db-user.md)
2. **CI runs as a user the grants script does not target.** `.github/workflows/api.yml` sets `DB_USER: user2grey`, `docker-compose.yml` creates `luxeknox`, and `0002_grants.sql:21` hardcodes `WHERE user = 'luxeknox'`. In CI the procedure's `IF EXISTS` is false, so the whole body is skipped. The `user2grey` value comes from the hardcoded fallback in `client.ts:33-34`. → [F-03](./F-03-least-privilege-db-user.md)
3. **The committed OpenAPI artifact is orphaned.** M0-24 names `docs/openapi/v1.yaml`, but `scripts/dump-openapi.ts:38-40` writes `v1.json` only. The 245 KB `v1.yaml` in the repo is regenerated by nothing and CI never checks that the artifact it does generate was committed. → [F-14](./F-14-e2e-ci-gaps.md)

## Decisions taken in this register

| Topic | Decision | Task |
| :--- | :--- | :--- |
| Migration credentials | Migrations and grants run as a **separate admin user** (`DB_ADMIN_USER`). The app user never holds DDL rights. | F-03 |
| Audit immutability | Enforced by **table-level privileges**, not triggers. MySQL cannot revoke a table-level slice of a database-level grant, so the database-level grant is dropped and per-table grants are re-issued. | F-03 |
| Grants re-application | Grants live in `drizzle/repeatable/` and re-run on **every** migrate, so tables added by future migrations are covered. | F-03 |
| Env fallbacks | No silent credential defaults. Missing `DB_USER`/`DB_PASSWORD`/`DB_ADMIN_*` throws at startup. | F-03 |
| Collation | `utf8mb4_0900_ai_ci` is required, not preferred. A server that rejects it fails the migration. | F-04 |
| Wildcard permissions | `'*'` stays the internal guard fast-path. `GET /me` returns expanded slugs and never leaks the sentinel. | F-08 |
| Route prefix | `setGlobalPrefix('v1')` is always applied, so the allowlist carries `/v1/...` forms only. | F-09 |
| Testcontainers | **Not adopted.** The CI service container already provides a clean pinned MySQL 8.4; M0-24 is amended to describe what exists, and e2e gets an explicit `resetTestData()` instead. | F-14 |
| OpenAPI artifact | One generated file, `docs/openapi/v1.json`. The orphaned `v1.yaml` is deleted and CI fails when the committed JSON is stale. | F-14 |

## Out of scope

Role CRUD, settings upsert, permission-cache TTL/invalidation wiring, password reset, idempotency store, and anything else `todo/README.md` lists under "Out of Module 0". `PermissionCache` having no TTL is correct for Module 0 — there is no endpoint that mutates roles yet.
